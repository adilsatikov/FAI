LECTURE 1 · BIOME 1

Spawn Meadow: Agents & Environments

ADILWhere am I? There is grass, a fence, and a small robot staring at me with one big eye.
CUBBYI am an agent. I read my sensors, I pick an action. Right now my sensors say: a person appeared. Action: wave. 👋 Welcome to the first lesson.

What is an agent?

An agent is anything that perceives its environment through sensors and acts on it through actuators. The environment is everything outside the agent that can change what it observes or how its actions turn out. A thermostat, a chess program, a robot vacuum and a self-driving car are all agents, just with very different amounts of intelligence.

Rational does not mean all-knowing

A rational agent picks the action that is expected to give the best performance, given what it has perceived so far. Notice the words expected and so far. Rationality is judged with the information the agent had before acting, not with hindsight.

RATIONAL AGENTUses the evidence it has, handles uncertainty explicitly, can still fail, judged by expected outcomes.
OMNISCIENT AGENTKnows the real future outcome of every action. Impossible in almost every real task.
MYTH vs FACTMyth: a rational agent never makes a bad decision. Fact: if you cross the road after checking both ways and still get splashed by a car from a hidden driveway, your decision was rational and the outcome was unlucky.

Four ingredients decide what is rational: the performance measure (what counts as success), the agent's prior knowledge, the actions it can take, and its percept history (evidence).

Four brains for four kinds of worlds

1 · REFLEXPercept → IF-THEN rule → action. Fast and easy to read, but brittle: it has no memory and no idea of the future.
2 · MODEL-BASEDKeeps an internal state, so it remembers what its sensors cannot show right now (the ghost that just went around the corner).
3 · GOAL-BASEDAsks "what will happen if I do this?" and searches or plans toward a goal. This is where the next lectures begin.
4 · UTILITY-BASEDGoals are yes/no. Utility is a score, so the agent can trade off speed against safety under uncertainty.

Richer reasoning usually costs more computation and more design effort. A good engineer picks the simplest architecture that fits the environment.

From rules to search to decisions

A reflex agent is not enough when good moves depend on the future. A goal-based agent needs a search problem: an initial state, the legal actions, a transition model (what an action does), a goal test and a path cost. When outcomes are random, we move on to a Markov decision process with states, actions, transition probabilities T(s'|s,a), rewards and a policy. The next chapters are exactly this staircase.

How do we know an agent is good?

Task performance (score, reward, safety, time) and model metrics (precision, recall, F1) answer different questions. A classifier with great accuracy can still be a poor agent if its mistakes are expensive.

Labyrinth Caves: Search, UCS & A*

ADILThere is a diamond at the far end of this cave, but the tunnels branch in every direction. Do I just wander?
CUBBYWandering is a strategy, but a bad one. We will model the cave as a search problem and let an algorithm decide which tunnel to explore next.

A search problem has five parts

  1. State space: every situation the planner cares about. A state keeps only the details needed for planning (an abstraction). For pathing, the state is just (x, y), not the colour of the sky.
  2. Successor function: the legal actions from a state and what each one costs.
  3. Start state.
  4. Goal test: a yes/no question, e.g. is (x,y) = END?
  5. Path cost: the sum of step costs. A solution is a sequence of actions from START to GOAL.

Example from class: cities are states, roads are actions with cost equal to distance, start = Astana, goal test = "is the state Almaty?". Search powers Google Maps, Pac-Man pathfinding, robot navigation, puzzle solvers, scheduling and network routing.

State-space graph vs. search tree

The state-space graph shows every state once. The search tree is a "what if" tree of plans: each node stands for a whole path from the start. The same state may appear many times in the tree, and we can never build the whole thing, so we grow it only as needed. The unexplored edge of the tree is the fringe (also called the frontier). The only real question every algorithm answers is: which fringe node do we expand next?

BFS: explore in rings

Breadth-first search expands every node at depth 1, then depth 2, and so on, like water filling a cave. It is complete on finite problems and optimal when every step costs the same. The price is a huge fringe and no respect for different step costs.

from collections import deque
def bfs(graph, start, goal):
    queue = deque([(start, [start])])      # one plan: just the start
    while queue:
        state, path = queue.popleft()      # oldest plan first (FIFO)
        if state == goal: return path
        for nxt in graph[state]:
            queue.append((nxt, path + [nxt]))   # new list, old path untouched
    return None

DFS: dive first

Depth-first search follows one tunnel as far as it goes, backs up at a dead end and tries the next branch. It uses a stack, so the whole change from BFS is popleft() becoming pop(). It can use little memory but may return a long solution. A visited set stops it from circling forever. Iterative deepening runs depth-limited DFS with limit 1, 2, 3, … to get DFS-like memory with BFS-like preference for shallow answers.

UCS: pay attention to the price

Suppose A→B costs 2, B→F costs 10, A→C costs 8, C→F costs 1. Both routes use two actions, so BFS sees a tie. But A-B-F costs 12 and A-C-F costs 9. Uniform-cost search always expands the fringe node with the smallest g(n), the exact cost paid so far. With positive step costs it is complete and optimal.

A*: pay attention to the price and the destination

UCS asks "what have I paid?". A* also asks "how far do I probably still have to go?".

f(n) = g(n) + h(n)
  • g(n): actual cost from START to n.
  • h(n): heuristic, an estimate of the remaining cost to the goal.
  • f(n): estimated cost of the best full path through n.
g(n) cost so far

CRAFTING RECIPECombine the cost already paid with an optimistic guess about the rest. A* expands the node with the smallest result.

Decision example. Node A has g=4, h=8, so f=12. Node B has g=7, h=2, so f=9. A* expands B: it is willing to have paid more so far because the total looks cheaper. If h(n)=0 everywhere, A* is exactly UCS.

Admissible heuristics

A heuristic is admissible (optimistic) if 0 ≤ h(n) ≤ h*(n), where h*(n) is the true cheapest cost to a goal. It never overestimates. On a grid with 4-direction moves, the Manhattan distance |x₁−x₂| + |y₁−y₂| is admissible when each step costs at least 1.

Why A* tree search is optimal (proof sketch from the lecture)

Let A be an optimal goal and B a suboptimal goal, both reachable. Some ancestor n of A is always on the fringe. Then f(n) = g(n)+h(n) ≤ g(A) = f(A) because h is admissible and h=0 at a goal. And f(A) = g(A) < g(B) = f(B) because B is suboptimal. So f(n) < f(B): n is expanded before B, and so on up the chain, until A is expanded before B.

WATCH OUTAn over-estimating heuristic may make A* faster but it can lose the optimality guarantee. For graph search (avoiding repeated states) the textbook condition is slightly stronger, a consistent heuristic. Try it in the lab below.

Hill Country: Local Search & Optimization

ADILI do not care how I get to the top of the tallest peak. I only want to be there. Does the route even matter?
CUBBYExactly the shift in this lecture. Sometimes the final configuration is the answer and the path is irrelevant. Then A* is the wrong tool.

From finding paths to improving configurations

Local search starts with one complete candidate solution and repeatedly tries to improve it with a small change. It keeps one or a few states in memory instead of a big fringe, so it uses almost constant space. Typical problems: n-queens, the travelling salesperson problem (TSP), timetables, chip layout.

STATEOne complete configuration (a full tour, a full board).
NEIGHBORA small change to it: move one queen, swap two cities.
OBJECTIVEOne number that says how good a state is. Maximize it (fitness) or minimize it (route length, conflicts).

Hill climbing

Look at the neighbors, move to the best better one, repeat until no neighbor improves. On values = [1, 3, 5, 8, 6, 4, 2] starting at index 0: 1 → 3 → 5 → 8. At 8 the neighbors are 5 and 6, neither is better, so the algorithm stops and returns 8.

def hill_climbing(values, start):
    current = start
    while True:
        neighbors = []
        if current > 0:                neighbors.append(current - 1)
        if current < len(values) - 1: neighbors.append(current + 1)
        best = current
        for n in neighbors:
            if values[n] > values[best]: best = n
        if best == current: break     # no neighbor is better: stop
        current = best
    return current

Where hill climbing gets stuck

LOCAL MAXIMUMA peak higher than its neighbors but lower than another peak elsewhere.
PLATEAUMany neighbors have the same value, so there is no slope to follow.
RIDGEThe way up needs a sequence of moves, none of which improves by itself.

Three ways out

  • Random restart: run hill climbing from many random starts and keep the best result. More computation, less dependence on one unlucky start.
  • Simulated annealing: sometimes accept a worse move. With ΔE = new − current (maximizing), always accept ΔE > 0; otherwise accept with probability exp(ΔE / T). The temperature T falls over time (T *= 0.95): explore early, refine later. Cool too fast and you freeze in a poor state; too slow and you waste time.
  • Local beam search: keep K states, generate all their successors, keep the best K. The K searches share information, so a good region found by one attracts the others. It is not the same as K independent hill climbs.
accept worse move with probability p = eΔE / T

Genetic algorithms: evolution as a search engine

A genetic algorithm keeps a whole population of candidates and cycles through: fitness (score each one) → selection (resample the fitter ones) → crossover (combine pairs) → mutation (random small changes) → new generation, until a stopping rule is met. The variety from mutation keeps the population from collapsing into one idea.

Case: the delivery courier in Astana

Eight stops: the university campus, Baiterek, EXPO, the Botanical Garden, Khan Shatyr, the National Museum, the railway station and the airport. State: a full tour that visits every stop. Neighbor: swap two stops or reverse a segment (2-opt). Objective: minimize total length.

f(route) = Σ d(cityᵢ, cityᵢ₊₁) + d(cityₙ, city₁)

Class question: a route was 76 km; after swapping two addresses it is 68 km. Would hill climbing accept it? Yes, the objective fell, so it is an improving neighbor.

Continuous worlds and gradient descent

States can be real numbers too. You can discretize a grid and reuse discrete methods, perturb values randomly, or follow the slope. Gradient descent moves against the gradient: x ← x − α ∇f(x), where α is the step size (learning rate). At an extremum the gradient is zero. Example: place 3 mobile clinics to minimize the sum of squared distances from villages to their nearest clinic. The coordinates are continuous variables, and the same move-and-improve idea applies.

x ← x − α ∇f(x)

Duel Arena: Game Trees, Minimax & Alpha-Beta

ADILA rival builder challenges me to a duel of wits. Whatever I do, they will answer. How do I plan against someone who plans against me?
CUBBYPut the opponent inside your search tree. Ordinary search asks "which sequence of my actions reaches the goal?". Adversarial search asks "which action is best after the opponent's best reply?".

Games as search problems

A game gives us states, actions, a transition function, a terminal test (has the game ended?) and a utility for each terminal state. Games come in flavours: deterministic or stochastic, two-player or multi-player, zero-sum or general-sum, perfect or imperfect information. This lecture focuses on deterministic, two-player, zero-sum games.

ZERO-SUMOne utility scale, opposite goals. MAX maximizes V(s); MIN minimizes V(s). My win is your loss.
GENERAL-SUMPlayers may have independent utilities. Cooperation, competition and indifference can coexist; terminal values can be tuples.

Tic-tac-toe as a game tree: X has 9 moves, then O has 8 replies, turns alternate until a win, loss or draw. Utilities can be +1 / 0 / −1. The full tree is finite but already far larger than a single board.

Minimax: assume the opponent is smart

Terminal: V(s) = U(s)
MAX node: V(s) = max V(s′)
MIN node: V(s) = min V(s′)

Values start at the leaves and are backed up the tree. The root value is the best outcome MAX can guarantee against optimal opposition.

Worked tree from the lecture

Three MIN nodes under a MAX root. Left: min(3, 12, 8) = 3. Middle: min(2, 4, 6) = 2. Right: min(14, 5, 2) = 2. Root: max(3, 2, 2) = 3.

WHY MAX DOES NOT CHOOSE 14The leaf 14 exists in the right subtree, but MIN controls the next move there and would choose 2. Minimax measures what MAX can guarantee, not the biggest number anywhere in the tree.
def minimax(state, maximizing):
    if is_terminal(state): return utility(state)
    if maximizing:
        value = float("-inf")           # any real value will beat this
        for child in successors(state):
            value = max(value, minimax(child, False))
        return value
    else:
        value = float("inf")
        for child in successors(state):
            value = min(value, minimax(child, True))
        return value

Minimax is optimal against an optimal opponent and conservative, but it is expensive: with branching factor b and depth m the tree has about O(bm) nodes. Do we really have to look at every branch? No.

Alpha-beta pruning: skip what cannot matter

Carry two numbers down the tree: α = the best value MAX can already guarantee on this path, β = the best value MIN can already guarantee. Prune when α ≥ β: the remaining siblings cannot change the decision.

At MAX: α ← max(α, v) cutoff if v ≥ β
At MIN: β ← min(β, v) cutoff if v ≤ α
Initial call: α = −∞, β = +∞

In our tree the left MIN node gives 3, so α = 3 at the root. In the middle MIN node the first leaf is 2 ≤ 3. MIN can already force 2 there, which MAX will never prefer over 3, so the leaves 4 and 6 are pruned. Pruning changes the work, not the root value. How much it saves depends on move ordering: look at promising moves first and you get tighter bounds, more cutoffs and deeper search in the same time.

Real games: depth limits and evaluation functions

Real games cannot be searched to the end. So we search to a depth limit d and, at the cutoff, replace the true utility with an estimate called an evaluation function. It is the agent's idea of what "good" means. A common form is a weighted sum of features:

Eval(s) = w₁f₁(s) + w₂f₂(s) + … + wₙfₙ(s)

For chess, features might be material, mobility, king safety and centre control. Do not confuse this with an A* heuristic: a heuristic estimates the remaining path cost, an evaluation function estimates the strategic quality of a position. Both inject domain knowledge, and evaluation functions also help order moves for alpha-beta. Iterative deepening gives an anytime algorithm: always have a decent move ready when time runs out.

Horizon effect: a depth limit can hide a disaster just past the frontier, so a position that looks great may be lost one move later. Deeper search helps but does not remove the problem.

When the opponent is luck: expectimax

Dice, slipping robots and a randomly moving ghost are not enemies. Assuming the worst case is then too pessimistic. In expectimax, MAX nodes still maximize, but chance nodes compute the probability-weighted average:

V(chance) = Σ P(s′) · V(s′)

Example: outcomes 8 (prob 1/2), 24 (1/3), −12 (1/6): (1/2)·8 + (1/3)·24 + (1/6)·(−12) = 4 + 8 − 2 = 10.

MINIMAXUse when the other side is a strategic, optimal opponent.
EXPECTIMAXUse when uncontrolled outcomes are better described by probabilities.

Match the model to the world: chance assumption against a real adversary is dangerous optimism; worst-case assumption against a random world is unnecessary pessimism. Modelling assumptions can matter as much as search depth.

Lava Fields: MDPs & Reinforcement Learning

ADILThe diamond is across a field of lava. The ground sometimes slips under my boots. A single path will not save me.
CUBBYRight: with slipping, a path is not enough. You need a policy: what to do from every square you might end up on. That is what a Markov decision process gives us.

Why sequential decisions are hard

The action that looks best now may be poor in the long run. An industrial machine: CONTINUE gives +10 production now but raises temperature and failure risk; MAINTENANCE costs −15 now but can prevent a −200 failure. Because every action changes the next state, we must optimise expected long-term return, not only immediate reward.

CLASSICAL SEARCHReturns a sequence: START → RIGHT → RIGHT → UP → GOAL. Works if outcomes are predictable.
MDP PLANNINGReturns a policy: what to do in each state. If RIGHT slips into DOWN, the policy still knows what comes next.

The state must contain what matters. For a battery controller, "charge level" alone cannot tell a cheap hour from an expensive hour, so the state needs (charge, price, demand, solar, hour). If relevant information is missing from the state, no algorithm can learn to use it. Uncertain moves can be simulated: random.random() < 0.8 → RIGHT, < 0.9 → UP, otherwise DOWN.

Expected value

E[R] = Σ pᵢ rᵢ = 0.9·(+10) + 0.1·(−50) = 4

Reward, return and value are three different things

  • Reward is local: what happened right after this action. A square next to the goal may have reward 0.
  • Return adds up the future with discounting: G = R₁ + γR₂ + γ²R₃ + …
  • Value is the expected return from here. A zero-reward square can be very valuable if it leads to +100 next.
G = 5 + 0.9·10 + 0.9²·20 = 30.2

γ is a modelling choice about the effective horizon. The same reward 10 steps away is worth γ¹⁰·100: about 0.10 at γ=0.5, 10.74 at 0.8, 34.87 at 0.9 and 90.44 at 0.99.

V, Q and the Bellman idea

V^π(s) rates a state under policy π. Q^π(s,a) rates a state-action pair: "if I take RIGHT now and then follow π, what return do I expect?". They connect through the best action: V*(s) = maxₐ Q*(s,a). If Q(A,LEFT)=2, Q(A,RIGHT)=8, Q(A,UP)=4, Q(A,DOWN)=−5, then V*(A)=8 and the optimal action is RIGHT.

The Bellman principle splits a long future into now + later: current value = immediate reward + discounted value of what follows. On a chain A → B → GOAL(10) with step reward −1 and γ=0.9: V(B) = −1 + 0.9·10 = 8, then V(A) = −1 + 0.9·8 = 6.2. A state is valuable because it leads to valuable states.

V*(s) = maxa Σs′ P(s′|s,a) [ R + γ V*(s′) ]

Stochastic example: RIGHT leads 80% to GOOD (V=10) and 20% to BAD (V=−5), step reward −1, γ=0.9. Then Q(s,RIGHT) = 0.8·[−1+0.9·10] + 0.2·[−1+0.9·(−5)] = 6.4 − 1.1 = 5.3.

Fork in the road: planning or learning?

PLANNING · model knownWe can query P and R. Use dynamic programming: value iteration (repeat Bellman optimality backups on all states) or policy iteration (evaluate a policy, then improve it greedily, repeat).
LEARNING · model unknownWe only see transitions and rewards from experience or a simulator. This is reinforcement learning.

Value iteration on a chain with a goal worth 10, γ=0.9, step reward −1: sweep 0: [0, 0, 0, 10]; sweep 1: [0, 0, 8, 10]; sweep 2: [0, 6.2, 8, 10]; sweep 3: [4.58, 6.2, 8, 10]. Information about the goal flows backwards, one state per sweep.

import numpy as np
gamma, V, goal_value = 0.9, np.zeros(4), 10
for k in range(5):
    new_V = V.copy()
    new_V[2] = -1 + gamma * goal_value
    new_V[1] = -1 + gamma * V[2]
    new_V[0] = -1 + gamma * V[1]
    V = new_V
    print(k, np.round(V, 2))

Reinforcement learning

An RL agent loops: observe Sₜ → choose Aₜ → environment responds → receive Rₜ₊₁ and Sₜ₊₁ → update knowledge. Nobody tells it the "correct" action; feedback can be delayed; and its own behaviour decides what data it sees. Unlike supervised learning (input → label), RL learns from consequences. Experience arrives as tuples (s, a, r, s′). An episodic task ends in a terminal state; a continuing task (HVAC, a power grid) never does.

Explore or exploit?

Exploit = pick the action you currently believe is best. Explore = try something uncertain to learn if your beliefs are wrong. Too little exploration locks you into a mediocre policy; too much wastes reward. The simple compromise is ε-greedy: with probability ε act randomly, otherwise take argmax Q(s,a).

Learning from surprise: TD error

Monte Carlo waits for a full episode and moves V toward the observed return. Temporal-difference (TD) learning updates after one step, using a reward plus another prediction (bootstrapping):

δ = R + γ V(S′) − V(S)

Example: V(A)=5, reward=2, V(B)=8, γ=0.9. Target = 2 + 0.9·8 = 9.2, error δ = 9.2 − 5 = 4.2. Positive: A was better than predicted, raise its value.

Fog Swamp: Probability & Bayesian Networks

ADILThe grass by the swamp hut is wet. Did it rain? Or did someone turn on the sprinkler? I cannot be sure.
CUBBYReal sensors are noisy and incomplete. A fever does not prove a disease, a hot motor does not guarantee failure. So AI assigns degrees of belief and updates them with evidence.

Probability in four lines

  • A random variable maps uncertain outcomes to values: Rain ∈ {True, False}, Weather ∈ {Sunny, Cloudy, Rainy}.
  • A distribution gives every outcome a probability and they must sum to 1: P(Rain=True)=0.20, P(Rain=False)=0.80; or 0.50 + 0.30 + 0.20 for sunny, cloudy, rainy.
  • Picture 100 equally likely days. A probability is a share of those days.
  • Conditioning changes the reference population.

Out of 100 days: rain + heavy traffic 24, rain + light 6, no rain + heavy 21, no rain + light 49. Heavy traffic overall: 45/100 = 45%. But look only at the 30 rainy days: 24 are heavy, so P(Heavy | Rain) = 24/30 = 80%. The denominator changed from 100 to 30.

Bayes' theorem: reverse the question

P(H | D) = P(D | H) × P(H) / P(D)
PRIOR P(H)belief before the evidence
LIKELIHOOD P(D|H)how expected the evidence is if H is true
EVIDENCE P(D)total chance of seeing D; makes things sum to 1
POSTERIOR P(H|D)updated belief

The medical test. Prevalence 1%, sensitivity P(+|D)=0.95, false-positive rate P(+|¬D)=0.10. A patient tests positive. What is P(D|+)? Evidence: P(+) = 0.95·0.01 + 0.10·0.99 = 0.1085. Posterior: 0.0095 / 0.1085 = 8.76%. Most people guess about 95%. They confuse P(+|D) with P(D|+). With natural frequencies: of 10,000 people, 100 are ill (95 test positive), 9,900 healthy (990 test positive). Among positives, 95 / (95+990) ≈ 8.76%.

Bayesian networks

A full joint table over n binary variables has 2ⁿ entries, far too many. A Bayesian network stores only local relationships: a directed acyclic graph (DAG) whose nodes are random variables and arrows are direct dependencies, plus a conditional probability table (CPT) for each node.

P(X₁,…,Xₙ) = Π P(Xᵢ | Parents(Xᵢ))

P(R, S, W) = P(R) · P(S | R) · P(W | R, S)

Priors: P(Rain)=0.20. P(Sprinkler | Rain) = 0.01, P(Sprinkler | no Rain) = 0.40. Two binary parents give 2² = 4 rows. Each row is its own little distribution.

Three shapes that decide who talks to whom

CHAIN A → B → CA ⟂ C given B. Knowing B blocks the path.
FORK A ← B → CA ⟂ C given B. A common cause explains both.
COLLIDER A → B ← CA and C are independent, but observing B (or its child) opens the path.

Explaining away: wet grass can come from rain or the sprinkler. Seeing wet grass makes both plausible, but learning the sprinkler was on makes rain less necessary. Competing explanations for one effect. (Our full network also has Rain → Sprinkler, so the pure collider example is only approximate here.)

Inference: asking the network a question

Exact inference by enumeration. We want P(Rain | Wet). Sum out the hidden Sprinkler.

Rain=T: 0.20 × [0.01·0.99 + 0.99·0.80] = 0.16038
Rain=F: 0.80 × [0.40·0.90 + 0.60·0.00] = 0.28800
P(Rain | Wet) = 0.16038 / (0.16038 + 0.288) = 35.77%

Wet grass moved the belief in rain from 20% to about 36%: evidence for rain, not proof. Variable elimination avoids repeated work by multiplying factors and summing out one hidden variable at a time (order matters for cost).

P_RAIN = 0.20
def p_sprinkler(rain): return 0.01 if rain else 0.40
def p_wet(rain, sprinkler):
    return {(True,True):0.99,(True,False):0.80,(False,True):0.90,(False,False):0.00}[(rain,sprinkler)]
def joint_rain_wet(rain):
    pr = P_RAIN if rain else 1 - P_RAIN
    total = 0.0
    for s in [True, False]:                 # sum over the hidden variable
        ps = p_sprinkler(rain); ps = ps if s else 1 - ps
        total += pr * ps * p_wet(rain, s)
    return total
num, other = joint_rain_wet(True), joint_rain_wet(False)
print(round(num / (num + other), 4))        # 0.3577

Deep Mine: Hidden Markov Models

ADILIt is pitch dark down here. I only hear taps from the machine behind the wall: sometimes high and sharp, sometimes dull. Is it healthy or about to break?
CUBBYThe real condition is hidden. You only get noisy observations. A single high reading does not prove a fault, but a sequence of readings, combined with a model of how machines change, can say a lot.

Hidden state vs. observation

HIDDEN · what we wantMachine condition: Healthy, Degrading, Faulty.
OBSERVED · what we measureTemperature, vibration, alarm status. Readings are noisy and can be false alarms.

A fault can exist before an alarm appears, the same reading can have different causes, and past readings help interpret a new one.

Step 1: Markov chain

A Markov chain describes how a system moves between states. The Markov assumption says the future depends on the present only: P(Xₜ₊₁ | Xₜ, Xₜ₋₁, …) = P(Xₜ₊₁ | Xₜ). The current state summarizes the history that matters.

from \ toHealthyFaulty
Healthy0.900.10
Faulty0.200.80

Each row sums to 1. One-step prediction: pₜ₊₁ = pₜ × T. If today's belief is [Healthy 0.80, Faulty 0.20] then P(Healthy next) = 0.80·0.90 + 0.20·0.20 = 0.76 and P(Faulty next) = 0.80·0.10 + 0.20·0.80 = 0.24. For k steps use pₜ × Tᵏ.

import numpy as np

p = np.array([0.80, 0.20])
print(p @ T)        # [0.76 0.24]  (@ is matrix multiplication)

An HMM has two linked sequences: hidden states X₁ → X₂ → X₃ … (horizontal arrows are transitions) and observations E₁, E₂, E₃ … (vertical arrows are emissions). Three ingredients define it:

π · INITIALP(state at start): 80% Healthy, 20% Faulty.
T · TRANSITIONHow the hidden state changes: Healthy → Faulty = 10%.
O · EMISSIONWhich readings each state produces: P(High | Faulty) = 0.70.
EmissionNormalHigh
Healthy0.800.20

DO NOT CONFUSEP(High | Faulty) = 0.70 is not P(Faulty | High). To reverse the condition we need Bayes' rule, exactly as in the swamp.

One reading. Prior [0.80, 0.20], sensor says HIGH. Scores: Healthy 0.80·0.20 = 0.16, Faulty 0.20·0.70 = 0.14. Total 0.30. Posterior: Healthy 0.16/0.30 = 53.3%, Faulty 0.14/0.30 = 46.7%. The machine did not change; our information did.

FilteringWhat is the state now?predict → weight by reading → normalize (SUM)

Filtering: predict, observe, correct, normalize

belieft(j) ∝ Oj(et) × Σi belieft−1(i) · Tij

Two HIGH readings in a row. After the first: [0.533, 0.467]. For the second, predict: Healthy 0.5333·0.90 + 0.4667·0.20 ≈ 0.5733, Faulty 0.5333·0.10 + 0.4667·0.80 ≈ 0.4267. Correct with HIGH emission: [0.5733·0.20, 0.4267·0.70] = [0.1147, 0.2987]. Normalize by 0.4133: [0.277, 0.723]. After two HIGH readings the chance of Faulty is 72.3%.

T = np.array([[.9,.1],[.2,.8]]); O = {'High': np.array([.2,.7])}
belief = np.array([.8,.2])
for t, reading in enumerate(['High','High']):
    if t > 0: belief = belief @ T       # predict (skip at time 1)
    belief *= O[reading]                # correct
    belief /= belief.sum()              # normalize

Prediction after filtering: from [0.277, 0.723], one step ahead gives Healthy 0.277·0.90 + 0.723·0.20 ≈ 0.394, Faulty ≈ 60.6%.

Smoothing: use the future to reconsider the past

Filtering at time 1 gave Faulty₁ = 46.7%. But the second HIGH is informative about time 1. Backward likelihoods: if Healthy₁, P(High₂|H₁) = 0.90·0.20 + 0.10·0.70 = 0.25. If Faulty₁, P(High₂|F₁) = 0.20·0.20 + 0.80·0.70 = 0.60. Multiply by the filtered belief: Healthy 0.5333·0.25 = 0.1333; Faulty 0.4667·0.60 = 0.28. Normalize: Faulty₁ = 0.28/0.4133 ≈ 67.7%. This is the forward-backward method.

Viterbi: the single best story

For HIGH, HIGH there are four paths: HH 0.0288, HF 0.0112, FH 0.0056, FF 0.0784. Viterbi keeps, for each current state, only the best path ending there: δₜ(j) = Oⱼ(eₜ) · maxᵢ[δₜ₋₁(i) · Tᵢⱼ] and remembers which predecessor won. Backtracking from the larger final score gives [Faulty, Faulty]. Note: picking the most likely state at each time separately is not Viterbi.

FILTERING · SUMCombines alternatives. Returns probabilities of the current state: P(F₂)≈72.3%.
VITERBI · MAXPicks the best alternative. Returns one best path: [F, F].

Crafting Village: Rational Decisions & Classical ML

ADILThe village furnace shows a vibration alarm. Repairing it costs a lot. Ignoring it could cost more. How do I decide?
CUBBYChain of thought for an AI system: data → prediction → utility → action. A model that predicts well is not automatically a system that decides well.

Rational action = maximum expected utility

A 90% success rate is not enough to judge an action, because success and failure may have very different consequences. Utility assigns a preference score to each outcome. The rational choice combines probability and utility:

EU(a) = Σᵢ P(oᵢ | a) · U(oᵢ) a* = argmaxa EU(a)

argmax returns the action, not the maximum value. If safety rules forbid some actions, maximize only over the feasible ones.

ProjectSuccessFailureExpected utility
A0.9 × 1000.1 × (−20)88
B0.6 × 2000.4 × (−50)100

B is riskier (lower success probability) but has higher expected utility, so under this utility scale it is the rational pick. Risk attitude matters: a risk-neutral agent maximizes expected money (utility linear in money); a risk-averse agent has concave utility and may prefer lower-variance outcomes.

actions = {'A': ([0.9, 0.1], [100, -20]), 'B': ([0.6, 0.4], [200, -50])}
def EU(probs, utilities): return sum(p*u for p, u in zip(probs, utilities))
scores = {name: EU(*v) for name, v in actions.items()}
print(scores, max(scores, key=scores.get))   # {'A': 88.0, 'B': 100.0} B

Delivery robot: the short route is faster but has a higher collision risk. Shortest path ≠ best decision when safety and uncertainty matter. Compare expected utility after pricing delay and collision.

Belief to action: maintenance threshold

Bayes tells us what to believe (prior → alarm → posterior). Decision theory tells us what to do. If continuing risks failure with probability p and cost C_fail, then the expected cost of continuing is p × C_fail; maintenance costs C_maint (assume it prevents failure). Maintain when

pfailure > Cmaint / Cfailure e.g. 2,000 / 10,000 = 0.20

The 20% threshold comes from costs, not from model accuracy. If failure becomes more expensive, the threshold drops.

Neuron Forge: Perceptrons & Neural Networks

ADILThe forge robot must decide if the floor ahead is STABLE or UNSTABLE. Nobody can write every rule by hand. Can it learn them from examples?
CUBBYThat is the whole idea of this biome: input → model → prediction → evaluation. We start with one artificial neuron, then stack them.

Learning from data instead of writing rules

In traditional programming a person writes the rules and the computer applies them to data. In machine learning we hand over data and the right answers, and the algorithm finds the rules (the model). The robot's inputs are two sensor readings between 0 and 1: grip and slip. The answer is a class: STABLE (1) or UNSTABLE (0).

CRAFTING RECIPEInputs times weights, plus a bias, give a score. The score decides the class.

Trees, logistic regression and Naive Bayes already share this pipeline. A neural network is another model in the same family, just much more flexible.

From a biological neuron to a perceptron

A biological neuron collects signals, and if the total is strong enough it fires. The perceptron copies this in the simplest way: multiply each input by a weight, add everything up with a bias, and fire if the sum is not negative.

z = w₁x₁ + w₂x₂ + b ŷ = 1 if z ≥ 0, otherwise 0

The weights say how much each input matters (a negative weight pushes toward UNSTABLE), the bias moves the threshold, and the step activation turns the score into a class. Take the lecture robot with w₁ = 2 (grip), w₂ = −3 (slip), b = −0.5:

GripSlipz = 2·grip − 3·slip − 0.5Output
0.80.21.6 − 0.6 − 0.5 = +0.5STABLE
0.80.81.6 − 2.4 − 0.5 = −1.3UNSTABLE

Regression vs classification: regression predicts a number (energy use), classification predicts a class (STABLE or not). The perceptron is a classifier.

Learning from error

Suppose the second row is really STABLE, but the perceptron said UNSTABLE. It made a mistake, so we nudge the weights toward the right answer. The perceptron learning rule uses the error e = y − ŷ and a learning rate η:

wᵢ ← wᵢ + η · e · xᵢ b ← b + η · e

Here e = 1 − 0 = +1, η = 0.1 and the inputs are (0.8, 0.8): w₁ = 2 + 0.1·0.8 = 2.08, w₂ = −3 + 0.08 = −2.92, b = −0.5 + 0.1 = −0.4. One update is only a nudge: z is now −1.072, still negative, so several updates may be needed. A correct prediction has e = 0 and changes nothing.

w1, w2, b, eta = 2, -3, -0.5, 0.1
x1, x2, y = 0.8, 0.8, 1
y_hat = 1 if w1*x1 + w2*x2 + b >= 0 else 0       # 0 (wrong)
e = y - y_hat
w1 += eta*e*x1; w2 += eta*e*x2; b += eta*e
print(round(w1, 2), round(w2, 2), round(b, 2))      # 2.08 -2.92 -0.4

Linear separability and why we need hidden layers

One perceptron draws one straight boundary. Data a line can split are linearly separable. In XOR-like data the STABLE points sit in opposite corners, so no single line works and the mistakes never reach zero. This limit, proved by Minsky and Papert in 1969, slowed neural network research for years.

The fix is to stack neurons. A network has an input layer, one or more hidden layers and an output layer. Information flows forward: each hidden neuron computes its own weighted sum, applies an activation, and passes the result on. Several hidden neurons cut the plane with several lines, and the next layer combines those pieces into a curved region.

Without a nonlinear activation, stacked layers collapse into one linear layer, so the activation function is what makes depth useful:

How a network learns

Training repeats three moves. 1. Forward pass: compute the prediction. 2. Loss: measure how wrong it is, for example the binary cross-entropy −[y·log p + (1−y)·log(1−p)]; a confident wrong answer is punished heavily. 3. Backward pass: backpropagation sends the error backward through the layers using the chain rule and gives every weight its gradient. Then gradient descent moves each weight a small step downhill:

w ← w − η · ∂Loss/∂w

One pass over all training data is an epoch. Too small a learning rate is slow; too large a rate overshoots and the loss jumps around. Rumelhart, Hinton and Williams made backpropagation famous in 1986.

Train, validation, test and overfitting

We split data into three parts: train (learn the weights), validation (choose settings such as H, η, when to stop) and test (one final honest grade). Training accuracy alone says how well the model memorized, not how it will behave on new floors.

Train accuracyTest accuracyVerdict
Model A98%65%Overfitting: memorized the training set
Model B91%89%Generalizes

Overfitting appears in the loss curves: training loss keeps falling, validation loss stops improving and then rises. Remedies: more data, a smaller network, early stopping at the validation minimum, regularization. In Lab 9B the gold-white dot marks that minimum.

Which mistake hurts more?

Call STABLE the positive class. A false positive (says STABLE, floor is not) can make the robot fall; a false negative (says UNSTABLE, floor is fine) only makes it slow. So here recall alone is not the goal: the costs of the two errors decide which threshold or metric to optimize.

Is the network worth it?

Always compare with a simple baseline. If logistic regression scores 82% and a neural network 88% (illustrative numbers), ask whether +6 points justify the extra data, compute and loss of interpretability. Then do error analysis: look at the failed cases (shiny floors? low light?) rather than only at the average.

Generalization is performing well on new data; memorization is storing training examples; neither is the same as understanding. A network can be accurate without knowing why, which is why validation and testing matter.

A glimpse of CNNs

For images, a fully connected network ignores the neighbourhood of pixels. A convolutional neural network slides small shared filters over the image, so the same edge detector is reused everywhere, and stacks them: edges → shapes → objects. The breakthrough moment was AlexNet in 2012.
